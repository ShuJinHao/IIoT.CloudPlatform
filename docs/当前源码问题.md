# 云端当前源码问题

> **状态：第 0～7 批候选代码保留；下列复审问题尚未全部收口，当前不是生产基线。**

本文是 Cloud 唯一活动短路线图，只保留尚未完成或候选实现尚未通过本批验证的问题。长期口径以[云端规则](./云端规则.md)和[过站工序扩展规则](./过站工序扩展规则.md)为准；已关闭问题和实施过程只从 Git、PR 与不可变验证证据追溯。候选实现不等于生产基线。

## 待确认观察

以下事项只记录待确认风险，不授权直接修改业务语义。

### CLOUD-TEMP-OBS-001：接口与数据库字段长度不一致

- 目标规则：[工序、设备插件、PLC 与生产查询](./云端规则.md#2-工序设备插件plc-与生产查询)及[身份、人员与权限](./云端规则.md#4-身份人员与权限)。
- 当前缺口：EmployeeNo/RealName 与 DeviceName 的接口上限大于数据库字段上限，合法请求可能最终变成数据库异常。
- 后续批次：`CLOUD-OBS-01`。
- 验收条件：确认统一上限后，接口、领域、数据库和错误语义一致，并覆盖边界值迁移与测试。

### CLOUD-TEMP-OBS-002：Device 到 Process 缺少数据库外键

- 目标规则：[工序和设备插件目录](./云端规则.md#21-工序和设备插件目录)。
- 当前缺口：设备所属工序完整性主要依赖应用检查，数据库未建立正式外键。
- 后续批次：`CLOUD-OBS-01`。
- 验收条件：确认外键及删除策略，存量数据预检通过，应用与数据库使用同一完整性语义。

### CLOUD-TEMP-OBS-003：工序编码唯一与输入规则未闭合

- 目标规则：[工序和设备插件目录](./云端规则.md#21-工序和设备插件目录)。
- 当前缺口：工序编码唯一比较区分大小写，输入长度和规范化规则未与数据库闭合。
- 后续批次：`CLOUD-OBS-01`。
- 验收条件：确认大小写、规范化和迁移规则后，创建、更新及数据库唯一约束一致。

### CLOUD-TEMP-OBS-004：设备注册与 BootstrapSecret 生成采用两阶段

- 目标规则：[发布系列、创建设备绑定和下载选择](./云端规则.md#31-发布系列创建设备绑定和下载选择)及[版本化 Binding、Pending 凭证和独立激活](./云端规则.md#34-版本化-bindingpending-凭证和独立激活)。
- 当前缺口：设备注册只产生 DeviceId/ClientCode，BootstrapSecret 到安装包生成时才创建或轮换，最终时点和重复生成失效口径尚未确认。
- 后续批次：`CLOUD-OBS-01`。
- 验收条件：明确两阶段契约、轮换与旧绑定失效规则，并覆盖注册、首装和重复生成。

### CLOUD-TEMP-OBS-005：内置角色模板是追加式最低权限

- 目标规则：[人员、账号和授权](./云端规则.md#42-人员账号和授权)。
- 当前缺口：播种会补回模板缺项但通常保留额外权限，尚未确认各内置角色应采用最低权限还是精确集合语义。
- 后续批次：`CLOUD-OBS-01`。
- 验收条件：逐个内置角色确认模板语义，升级只执行明确允许的增删且不覆盖现场自定义角色。

### CLOUD-TEMP-OBS-007：工序主数据写操作的真实角色尚未裁决

- 目标规则：[工序和设备插件目录](./云端规则.md#21-工序和设备插件目录)及[人员、账号和授权](./云端规则.md#42-人员账号和授权)。
- 当前缺口：工序主数据的创建、修改和删除分别属于哪个真实角色尚未形成最终业务决策；不得用未明确角色的泛称代替 `Admin`、运维员或其它实际角色。
- 后续批次：`CLOUD-OBS-01`，先确认业务口径再授权实现。
- 验收条件：逐项确认创建、修改、删除的调用者、权限、在用保护和审计规则；决策前不改变现有接口语义。

### CLOUD-TEMP-OBS-008：Admin 个人特批是否允许扩散治理权限

- 目标规则：[人员、账号和授权](./云端规则.md#42-人员账号和授权)。
- 当前缺口：个人特批由 Admin 专属维护，但尚未明确该入口是否也必须禁止向普通人员授予角色定义、角色权限维护等治理权限。
- 后续批次：`CLOUD-OBS-01`，先确认白名单或禁止集合。
- 验收条件：确认个人特批的治理权限边界后，权限目录、服务端校验、页面候选、存量预检和结构化审计使用同一口径。

### CLOUD-TEMP-OBS-010：事务与 Admin 授予静态门禁存在已知覆盖边界

- 目标规则：[复审出口](./云端规则.md#11-复审出口)。
- 当前缺口：手工事务执行策略和 Admin 角色授予目前主要由 ArchitectureTests 的 Roslyn/源码静态扫描约束；对新的间接封装、反射、非 C# 写入或其它未建模路径是否需要编译期 Analyzer 或数据库防线尚未确认。
- 后续批次：`CLOUD-OBS-01`，先建立绕过矩阵再决定是否加强。
- 验收条件：列出生产写入面的正反例和当前门禁可见性，确认接受的防线层级；任何加强不得通过宽泛字符串扫描误报或绕开现有受影响测试选择器。

## 配方冻结观察（非当前源码整改范围）

配方从当前裁决开始冻结，已有数据库、接口、页面、权限、审计和 CRUD 保留。以下观察不授权当前整改，不代表配方已接入生产；只有用户另行解除冻结并批准业务设计后才重新评估。

### CLOUD-TEMP-RECIPE-001：参数缺少目标值语义

- 目标规则：[配方](./云端规则.md#5-配方)。
- 当前缺口：标准参数只有标识、名称、单位、最小值和最大值，缺少设定值/目标值及升级保留语义。
- 后续批次：无；保持冻结，只有另行解除冻结后重新评估。
- 验收条件：执行值与范围值模型明确，创建、升级、页面和 Edge 获取不会丢失正式字段。

### CLOUD-TEMP-RECIPE-002：版本升级不保证单调递增

- 目标规则：[配方](./云端规则.md#5-配方)。
- 当前缺口：升级只检查格式，归档版本也可产生相同、较低或倒退版本。
- 后续批次：无；保持冻结，只有另行解除冻结后重新评估。
- 验收条件：版本比较、升级来源和冲突规则统一，新版本必须严格高于当前合法版本。

### CLOUD-TEMP-RECIPE-003：删除旧版本后可出现多个活动版本

- 目标规则：[配方](./云端规则.md#5-配方)。
- 当前缺口：删除旧 `V1.0` 后可重新创建同名活动版本，原有更高活动版本可能继续存在。
- 后续批次：无；保持冻结，只有另行解除冻结后重新评估。
- 验收条件：同一工序、设备和配方身份最多一个活动版本，删除历史不能重新打开并行活动版本路径。

### CLOUD-TEMP-RECIPE-004：数据库缺少关键唯一与活动版本约束

- 目标规则：[配方](./云端规则.md#5-配方)。
- 当前缺口：工序、设备、配方名称、版本及单活动版本主要依赖应用和分布式锁。
- 后续批次：无；保持冻结，只有另行解除冻结后重新评估。
- 验收条件：存量预检后建立数据库约束，并以并发 PostgreSQL 测试证明唯一性。

### CLOUD-TEMP-RECIPE-005：配方前后端权限与状态不一致

- 目标规则：[配方](./云端规则.md#5-配方)。
- 当前缺口：候选设备查询、删除按钮权限和可删除状态与后端规则不一致。
- 后续批次：无；保持冻结，只有另行解除冻结后重新评估。
- 验收条件：角色模板、候选查询、页面可见性、后端权限和版本状态使用同一口径。
